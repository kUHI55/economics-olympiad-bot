# Economy Theory Bot

Личный Telegram-бот для подготовки к олимпиадам по экономике. Это не решатель задач и не чат «обо всём»: он превращает подтверждённые пользователем конспекты, вебинары и учебные материалы в собственную базу теории, а затем тренирует активное воспроизведение.

Главная цепочка работы:

`источник → предложенные знания → подтверждение → вопросы → ответы → статистика → повторение`

## Что умеет MVP

- Главное меню `/start`: теория, проверка, повторение, прогресс, слабые места, добавление материала и настройки.
- Иерархия `раздел → тема → подтема → элементы знаний`; её можно пополнять из Telegram.
- Загрузка текста, TXT, Markdown, PDF и DOCX. Исходный текст и файл сохраняются вместе с названием, типом и датой.
- LLM-анализ только при загрузке: она предлагает элементы знаний и вопросы с обязательной цитатой из источника. Ничего не попадает в базу до кнопки «Сохранить».
- Вопросы на формулы, определения, обозначения, понимание, причинно-следственные связи, сравнение, типичные ошибки и тесты с одним правильным вариантом.
- Свободные ответы оцениваются только по вопросу, эталону, ключевым пунктам и релевантной цитате. При неуверенности вердикт — `uncertain`.
- После неверного ответа эталон не показывается: доступны повторная попытка, направляющая подсказка и отдельная кнопка показа ответа.
- Формулы проверяются детерминированно: простые эквивалентные записи вроде `U/LF` и `U·LF⁻¹` принимаются без LLM.
- История попыток, прогресс, слабые темы, интервальное повторение (1/3/7/14/30 дней), режимы блиц и экзамен.
- Ежедневное серверное напоминание в заданное время.

## Архитектура

```text
app/
  bot/                 # aiogram: обработчики, кнопки, FSM, middleware
  core/                # настройки и доменные перечисления
  database/
    models/            # SQLAlchemy-модели
    repositories/      # запросы к данным
  schemas/             # строгие схемы LLM-предложений и оценок
  services/
    theory/            # извлечение файла, анализ и публикация подтверждённого черновика
    quiz/              # подбор вопросов, детерминированные формулы, оценка
    progress/          # попытки, статистика, слабые места
    review/            # интервальное повторение
    notifications/     # ежедневные напоминания
    llm/               # изолированный адаптер провайдера
migrations/            # Alembic
tests/                 # unit-тесты
```

Telegram-слой не содержит бизнес-правил. База данных обслуживается SQLAlchemy 2.x, а изменения схемы — Alembic. Единственный сетевой интерфейс LLM изолирован в `app/services/llm/`; его можно заменить, не меняя сценарии бота.

## Данные и гарантии источника

`material_drafts` хранит непредложенный к публикации материал и JSON-предложение анализатора. Нажатие «Отмена» удаляет черновик; «Сохранить» в одной транзакции создаёт `sources`, `knowledge_elements`, `questions` и `question_options`.

Каждый элемент знаний и каждый вопрос несут `source_id` и `source_excerpt`. Анализатор дополнительно отбрасывает предложения, чья цитата не встречается в исходном тексте. Противоречащие друг другу источники не склеиваются: остаются отдельными связанными записями.

Для обучения используются `attempts`, `progress`, `review_schedule`, `quiz_sessions` и `session_questions`. Это позволяет позже добавить несколько пользователей без переделки модели.

## Требования

- Python 3.12–3.14
- Docker Engine + Docker Compose для production
- Telegram Bot Token
- PostgreSQL 16 (в Docker Compose уже настроен)
- ключ LLM-провайдера, совместимого с клиентом OpenAI, для анализа источников и оценки свободных ответов

## Создание бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather).
2. Выполните `/newbot`, задайте имя и username.
3. Скопируйте выданный токен в `BOT_TOKEN` файла `.env`.
4. Узнайте свой числовой Telegram ID и запишите его в `ADMIN_ID`. Только этот пользователь сможет добавлять и менять материалы.

## Настройка

```powershell
Copy-Item .env.example .env
```

Заполните `.env`. Минимальный пример:

```dotenv
BOT_TOKEN=123456:replace_me
ADMIN_ID=123456789
DATABASE_URL=postgresql+asyncpg://economy_bot:strong_password@postgres:5432/economy_bot
POSTGRES_PASSWORD=strong_password
LLM_API_KEY=replace_me
LLM_MODEL=gpt-5-mini
TIMEZONE=Asia/Yekaterinburg
REMINDER_HOUR=20
```

`DATABASE_URL` использует пароль пользователя `economy_bot`, а `POSTGRES_PASSWORD` задаёт тот же пароль для контейнера PostgreSQL. Файл `.env` намеренно исключён из Git.

## Локальный запуск без Docker

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
alembic upgrade head
python -m app.main
```

Перед локальным запуском PostgreSQL должен быть доступен по `DATABASE_URL`. Для проверки кода:

```powershell
python -m pytest
python -m ruff check .
```

## Запуск через Docker Compose

```bash
docker compose up --build -d
docker compose logs -f bot
```

Контейнер `bot` перед запуском polling применяет `alembic upgrade head`; оба контейнера используют `restart: unless-stopped`. Для остановки используйте `docker compose down` — том `postgres_data` не удаляется.

## Deploy на VPS

1. Установите Docker Engine и Docker Compose на VPS.
2. Скопируйте проект на сервер и создайте защищённый `.env` (например, `chmod 600 .env`).
3. Укажите production-токен, уникальный пароль PostgreSQL и свой `ADMIN_ID`.
4. Запустите `docker compose up --build -d`.
5. Проверьте `docker compose ps` и `docker compose logs -f bot`.

Бот работает внутри VPS, поэтому личный компьютер не нужен. Не запускайте несколько копий контейнера `bot`: в MVP ежедневный планировщик намеренно рассчитан на один экземпляр.

## Backup и восстановление PostgreSQL

На VPS создайте дамп (команда выполняется в shell хоста):

```bash
mkdir -p backups
docker compose exec -T postgres pg_dump -U economy_bot -d economy_bot -Fc > backups/economy_$(date +%F).dump
```

Для восстановления сначала остановите бота, затем восстановите дамп:

```bash
docker compose stop bot
cat backups/economy_YYYY-MM-DD.dump | docker compose exec -T postgres pg_restore -U economy_bot -d economy_bot --clean --if-exists
docker compose start bot
```

Проверяйте восстановление на отдельной базе перед заменой рабочего тома.

## Обновление

```bash
git pull
docker compose up --build -d
docker compose logs -f bot
```

Перед обновлением схемы сделайте backup. При старте контейнер применит новые миграции Alembic.

## Ограничения MVP

В первой версии нет олимпиадных и расчётных задач, сайта, платежей, рейтингов, голосовых ответов или распознавания рукописных формул. Если в сохранённых источниках недостаточно данных для надёжного вопроса, бот обязан отказаться от его генерации, а не дополнять материал собственной теорией.
